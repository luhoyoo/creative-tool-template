# 创意小工具模板

这是面向公司内部的 **React + Vite 工具起点**，包含一个可运行的股票合约海报示例。每个新工具可以从此公开模板创建自己的仓库；涉及公司内容时选择私有仓库，替换示例数据、素材和海报版式，再独立发布。

## 快速开始

1. 在 GitHub 模板页选择 **Use this template → Create a new repository**，根据内容选择仓库可见性；公司内部项目建议选择 **Private**。
2. 将新仓库下载到电脑，用 Codex 打开项目目录。
3. 复制 [需求填写表](docs/需求填写表.md)，填写需求和 Figma 链接，再连同 [Codex 提示词](docs/Codex制作提示词.md) 发给 Codex。
4. 安装 Node.js 后运行：

   ```bash
   npm install
   npm run dev
   ```

   打开终端显示的本地地址。生成生产构建：`npm run build`。
5. 本地验收通过后，按公司规定创建独立部署项目。连接 Git 仓库前确认访问权限、域名和发布范围。

## 示例中已有的能力

- 深色设置面板、单行自适应标题、实时预览；
- 标的数量选择、图片上传、圆形裁切、缩放与底色；
- 19 种示例语言、可折叠文案编辑、单张 PNG / 多语言 ZIP 导出；
- 移动端布局、键盘焦点、输入校验与导出状态。

这些是**示例实现**，不是对所有工具的通用承诺。新工具须根据设计稿和需求重新核对尺寸、语言、布局、导出及上传行为。

## 文件位置

| 位置 | 作用 |
| --- | --- |
| `src/config/tool.js` | 工具名称、描述及示例标的 |
| `src/config/copy.js` | 示例多语言文案，数组依次为顶部标签及三条权益文案 |
| `src/Stock.jsx` | 示例编辑界面、海报布局、预览和导出逻辑 |
| `src/stock.css` | 示例工具页面和海报样式 |
| `src/styles.css` | 通用基础样式及可访问性样式 |
| `public/assets/stock/` | 海报示例素材，制作新工具时核对授权并替换 |
| `docs/` | 需求表、Codex 提示词和验收清单 |
| `AGENTS.md` | Codex 工作指引 |

需要新增字段、不同尺寸或版式时，不能只修改配置文件，还需调整组件、样式和导出逻辑。仓库的品牌、图片、文案以及示例股票仅用于展示：新项目发布前应检查适用性和素材授权。

## 数据与访问

此示例在浏览器本地处理上传图片和生成文件，不提供账号系统、云端存储或访问控制。刷新页面会丢失未保存的编辑；GitHub 仓库私有不代表已部署的网站私有。不要把 API 密钥、内部客户数据、账号令牌或 `.env` 文件提交到仓库。涉及敏感资料时，先按公司安全要求确认使用、部署和访问方式。

## 安装 Codex Skill

仓库中附带 [`creative-tool-builder`](skills/creative-tool-builder/SKILL.md) Skill，包含工作流程、验收指引和可运行的起始工程。同事可以在 Codex 中发送：

```text
请使用 $skill-installer 从以下地址安装创意小工具制作 skill：
https://github.com/luhoyoo/creative-tool-template/tree/main/skills/creative-tool-builder
```

安装后在下一轮对话中使用：

```text
使用 $creative-tool-builder 制作一个【工具名称】。
用途：【填写使用人群和目标】
设计稿：【粘贴 Figma 画板链接】
编辑内容：【填写】
预览与导出：【填写尺寸、格式、语言和文件命名】
```

Skill 会在空项目中提供可运行的起点；在已有项目中则先读取并沿用现有技术栈。示例海报的品牌、素材和文案不是新工具的默认要求。
